# CLAUDE.md

Firmware for an **Ulanzi TC001** desktop clock (ESP32, 32x8 WS2812 LED matrix) that shows the round
countdown timer of a tournament on [Best Coast Pairings](https://www.bestcoastpairings.com).
C++ / Arduino framework / PlatformIO. Work in progress, not released. Rewritten from an earlier
MicroPython version (see README.md).

## General

- The local developer setup is in `CLAUDE.local.md` (gitignored) when it exists.
- Indent with 4 spaces.
- Most code is hand-written by the author; `lib/wifimgr` was largely generated by GitHub Copilot.
- Detailed documentation is in `docs/` (see "Documentation index"); read a document only when the task needs it.

## Every TC001 firmware: silence the buzzer first

The TC001 whistles loudly from power-on until firmware drives the passive buzzer pin (GPIO 15, floating
input). The very first statement of **every** firmware that runs on the TC001 must be
`pinMode(15, INPUT_PULLDOWN)`, before any other initialization (Serial, display, WiFi, delays). This applies
to the main application, device test suites and any firmware added in the future. The main application does
it as the first line of the `Tc001` constructor (`lib/hw/tc001.cpp`); device tests do it at the start of `setup()`.

## Build, flash, monitor

If `pio` is not on PATH, use PlatformIO's own `~/.platformio/penv/bin/pio` (and its `python` next to it);
the pre-commit hook always uses that path.

```sh
pio run                    # build production (env tc001 = configs/tc001.ini, default)
pio run -t upload          # flash production over USB
pio run -e tc001-dev -t upload   # flash dev build (debug output + console)
pio device monitor -b 9600 # serial console
pio test -e native         # unit tests on the host (lib/core, lib/webui)
pio test -e tc001          # unit tests on the TC001 (gfx, NVS, newlib time)
sh tools/build_configs.sh  # build every build configuration (configs/*.ini)
python tools/bcp_contract.py <eventId>  # contract test of the live BCP API (PlatformIO's python)
```

- Flash usage is ~85 % of the 1.25 MB app partition (dev build ~90 %). Watch the size when adding
  features/fonts/HTML.
- Opening or closing the serial port resets the ESP32.
- Device tests replace the firmware: stop devmon before, flash production again right after every run
  (the test firmware leaves the display frozen and the TC001 whistles).
- Build features: every build configuration `configs/*.ini` sets all `BCP_FEATURE_*` to 0/1; code uses `#if`
  (never `#ifdef`) after `#include <buildfeatures.h>`, which checks the dependencies. See `docs/features.md`.
- Dev build (`-e tc001-dev`, `BCP_DEV`): all development code is inside `#ifdef BCP_DEV`; the production build must
  stay byte-identical without it. `DEV_LOG("Module", msg)` prints only in the dev build.
- Logic that needs tests belongs to `lib/core` (no ESP-only includes, tested on the host).
- Dev console, devmon/devcmd helpers, test details, pre-commit hook, USB/freeze troubleshooting: `docs/dev-build.md`.

## Layout

PlatformIO's LDF picks up each folder in `lib/` as a library; headers are included as `<name.h>`.

| Path | Purpose |
|---|---|
| `src/main.cpp` | `setup()`/`loop()`: modes of the build, button events, mode switching, long Mid = config page |
| `src/mode.h`, `src/bcpmode.*` | `Mode` interface; BCP mode: data refresh every 60 s, display decisions (`updateDisplay()`), reboot after 5 failed fetches |
| `src/devconsole.*` | Serial command console, dev build only |
| `tools/` | Host-side dev helpers (`devmon.py`, `devcmd.sh`, `bcp_contract.py`, `build_release.sh`, `build_configs.sh`, `git-hooks/pre-commit`) |
| `configs/` | Build configurations (`tc001.ini` = release, `tc001-minimal.ini`): envs and feature switches |
| `install/`, `.github/workflows/` | Browser installer page (ESP Web Tools) and the release workflow (see `docs/dev-build.md`) |
| `test/native/`, `test/device/` | Unit tests on the host / on the TC001 |
| `lib/bcp/` | `CBCPEvent` singleton `BCPEvent`: BCP REST API, event data, RTC snapshot |
| `lib/core/` | Hardware independent logic, host-tested: parsing, countdown text/colour (`CountdownDisplay`), display/refresh policy, buttons (short/long press), mode IDs, battery level, alert icon cycle and connection alert, `DisplayState`, string helpers |
| `lib/hw/` | Abstract `Hw` interface (`hw.h`); `Tc001` singleton (matrix, buttons, display task, fonts, status overlay, battery ADC) |
| `lib/config/` | `CConfig` singleton `Config`: settings in NVS + on-demand HTTP config server |
| `lib/wifimgr/` | `CWifiMgr` global `WifiMgr`: multi-network WiFi, captive portal, NTP + RTC sync |
| `lib/devlog/` | `DEV_LOG` debug macro, dev build only |
| `lib/features/` | `buildfeatures.h`: feature switch checks and dependencies |
| `lib/webui/` | Shared look of the web pages (template, CSS, `escapeHtml`) |
| `lib/gfx/` | Adafruit_GFX helpers: `ScrollingText`, `ProgressIndicator`, `UTF8canvas16`, fonts |

## Key invariants

- Two tasks on core 1 draw to the same matrix: Arduino `loop()` and the `Tc001::handleEvents` task (10 ms).
  All display access in `tc001.cpp` goes through the recursive mutex `DisplayLock`; keep new drawing code
  inside it and slow work (HTTP, config server) outside.
- `displayState` (`lib/core/displaystate.h`) is set only by the `Hw` implementation; modes only read it.
- Modes pass countdowns to the `Hw` as `CountdownDisplay` copies, never pointers (the display task reads them).
- Buttons are polled in `handleEvents` and queued to `loop()`; modes handle them in `onButton()`.
- `Tc001` is a `Print` sink for `WifiMgr.connect()` and dispatches on the message prefix (`"Error:"`,
  `"Connecting "`, `"Connected "`); changing message texts in `wifimgr.cpp` changes what the display does.
- Countdown = `roundEndEpoch - time(nullptr)`, so the system clock must be valid UTC (NTP, RTC fallback).
- BCP API is unofficial; a round without a timer returns `200 {}`, 404 on the event = invalid event ID.
- `F3x5[]` is a segmented font terminated by an all-null entry; time fonts only cover `-` to `:`.
- Singletons: private ctor + friend `get...Instance()` + global reference (`BCPEvent`, `Config`).

## Code style

- File header: one-line description, `// (c) 2025 Honza Skýpala`, `// WTFPL license applies`.
- Classes `CName` for singletons, members with trailing underscore (`name_`), methods camelCase.
- Function names start with a verb; value getters are nouns (`name()`), bool getters use `is`/`has`.
- Section comments in the form `// ---- Section ----`.
- More: `docs/contracts.md`.
